nd?.f    N-Dimensional FFT

         When I began to creating these programs, I assumed
    that n(i) >= 3 ( i.e, data size of each dim. >= 2**3 = 8 ).
    Most programs works fine even for 1 <= n < 3, but user should
    examine whether each program works correctly, by his own hand,
    especially for 1 <= n <3.

    1:  Decimation In Time (DIT) method
    2:  loop merging at bit-reversal loop:
          This improvement maximizes the the length of the inmost loop.
    3:  real version of 2
    4:  calling multiple FFT + small work space
    5:  Similar to 25, but the way of using work space is slightly
        different from 25. -> recursive call (+first 5 special)
    6:  2 + special treatment in first decimation
    7:  recursive call (+last 3 special)
    8:  calling multiple FFT + transpose routine
    9:  8 + self sorting algorithm
    10: 7 + strided mfftnb(mfftnbs)
    11: multiple call of FFT + transpose routine
    12: multiple call of FFT without bit-reversal
    15: using small work space + calling multiple FFT without bit-reversal
          ( for effective use of cache line )
    16: 15 + using transpose instead of using small work space
           + avoiding bank conflict in transpose routine
    18: just a test for 20 (proto-type of 20)
		(calling multiple FFT + bit-reversal without bitrev)
    20: calling multiple FFT with minimum memory copy
           + bit-reversal without bitrev
           + 8, 4, 2 point DIT routine
           + special treatment for the first 8 point DIT
	20x: Same as 20. But data configuration is different.
         contiguous real part + contiguous imaginary part
         ( "nd20x" is 30% faster than "nd20", on Fujitsu VPP )
    21: Simplified 16 + transpose routine
        This seems to be better than 16 on some machines,
        in spite of extra memory copy.
    22: 19 + reducing outer loop count in the calculation of first dimension
         and increasing the inmost loop count.
        (This routine is not a best one, but fast on both
         scalar and vector machine.)
    24: 15 + 16, 8, 4, 2 point DIT
           + special treatment for the first 8 point DIT
    25: Similar to 24, but the way of using work space is slightly
        different from 24.

    fftw: using fftwnd from fftw library
    asl:  using JFCSSF from NEC's ASL
    mfft: using C3FFT  from mfft
    gpfa: using gpf3d  from Temperton's GPFA
    gpfa2:using gpfa2f from Temperton's GPFA & special transpose routine
            Special directives for the NEC's & Hitachi's vector machines
          are inserted by S. Yamamoto.
